# PickMe Taxi (Flutter)

Такси на Яндекс.Картах и Supabase: один APK, роль (пассажир / водитель) выбирается при регистрации.
Розовое оформление и карта из навигатора сохранены.

## Как это работает

**Пассажир:** выбирает точки (поиск или клик по карте, промежуточные остановки) → «Построить маршрут» →
видит время, расстояние и цену → выбирает оплату → «Заказать такси» → следит за машиной на карте.
Статусы: поиск водителя → водитель едет → на месте → в пути → завершено. Заказ можно отменить до начала поездки.
Избранное, история, «Дом/Работа» остались.

**Водитель:** включает «На линии» → получает новые заказы в реальном времени (ближайшие сверху) →
«Принять» → «Я на месте» → «Начать поездку» → «Завершить». Может отказаться от заказа (он вернётся в поиск).
Позиция водителя передаётся пассажиру, пока водитель на линии и приложение на экране.

## Запуск

1. **Supabase.** SQL Editor → вставьте и выполните весь `supabase_schema.sql`.
   В Authentication → Providers → Email на время разработки выключите «Confirm email».
2. Скопируйте в проект `lib/`, `assets/`, `pubspec.yaml`, `supabase_schema.sql` и папку `android/` целиком,
   затем `flutter pub get && flutter run`.
3. Зарегистрируйте два аккаунта (на двух телефонах или телефон + эмулятор): пассажира и водителя.
   Для проверки на эмуляторе задайте водителю и пассажиру позиции в настройках эмулятора.

## Структура

- `lib/main.dart`, `lib/router.dart` — запуск, вход/выход, маршруты (редирект на `/login`, если нет сессии)
- `lib/screens/auth/` — вход и регистрация (роль, для водителя — авто и госномер)
- `lib/screens/role_gate.dart` — выбирает клиентский или водительский экран по роли
- `lib/screens/home_screen.dart` — клиент: карта, поиск, маршрут, заказ такси
- `lib/screens/client_ride_screen.dart` — клиент: ход поездки
- `lib/screens/driver_home_screen.dart`, `driver_ride_screen.dart` — водитель
- `lib/services/` — `ride_service` (заказы), `driver_location_service` (позиция водителя),
  `payment_service` (оплата), `auth_service`, `yandex_api`, `supabase_service` (закладки)
- `lib/config.dart` — ключи и тариф (`Tariff`)
- `supabase_schema.sql` — таблицы, правила доступа (RLS), функции смены статусов, Realtime

## Тариф

Подача 100 ₽ + 20 ₽/км + 5 ₽/мин, минимум 150 ₽, округление до 10 ₽.
Итоговую цену считает **сервер** (триггер `rides_before_insert`), приложение показывает оценку.
Меняя тариф, правьте его в двух местах: `Tariff` в `lib/config.dart` и в `supabase_schema.sql`.

## Оплата

- **Наличные** работают: водитель получает деньги, заказ помечается оплаченным при завершении.
- **Картой** — пока **заглушка** (`StubPaymentService`): деньги не списываются, кнопка «Оплатить (тест)» лишь
  помечает заказ оплаченным. Чтобы подключить реального провайдера (ЮKassa, CloudPayments, Stripe и т.д.),
  реализуйте интерфейс `PaymentService`, а подтверждение платежа делайте на сервере (webhook → Supabase
  Edge Function), после чего удалите функцию `mark_ride_paid` из SQL.

## Безопасность

- Все данные защищены RLS: клиент видит только свои заказы, водитель — свои и свободные; прямых UPDATE
  заказов у приложения нет, статусы меняют серверные функции с проверкой роли и допустимого перехода.
- Роль нельзя поменять после регистрации.
- Ключи Яндекса лежат в `lib/config.dart`: ограничьте их по package name и SHA-1 в кабинете Яндекса.
- Расстояние и время приходят из приложения (OSRM), поэтому цену теоретически можно занизить подменой этих
  значений. Для продакшена считайте маршрут на сервере (Edge Function).

## Ограничения первой версии

- Позиция водителя передаётся только пока приложение открыто (нет фоновой службы геолокации).
- Нет push-уведомлений: новые заказы и статусы видны только при открытом приложении.
- Нет рейтингов, истории поездок, чата и звонков, нет пересчёта цены по факту маршрута.
- Заказы в статусе «поиск» старше 10 минут водителям не показываются (отдельной автоотмены на сервере нет).
- Экран подсказок поворотов («Через 200 м…») убран: в такси его заменяет экран поездки водителя.

## Сборка APK на GitHub

Workflow `.github/workflows/build-apk.yml` запускается при push в main/master, в pull request и вручную
(Actions → Build APK → Run workflow). Готовый `app-release.apk` лежит в артефактах запуска
(`navigator-app-release-apk`). При push тега `v1.0.0` APK прикрепляется к GitHub Release.
Workflow сам находит `pubspec.yaml`; папка `.github` должна лежать в корне репозитория.
Сборка идёт на JDK 21 (плагин yandex_maps_mapkit собран под Java 21), версии Gradle/AGP/Kotlin — из
шаблона Flutter 3.50 (`android/settings.gradle.kts`, `android/gradle/wrapper/gradle-wrapper.properties`).
APK подписан debug-ключом; для Google Play нужен собственный keystore.
